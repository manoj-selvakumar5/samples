# Contributing Samples Guide







Thank you for contributing to the Strands Agents samples repository! This guide will help you create high-quality samples that are easy to use and maintain.

## Quick Start

Before submitting a sample, please review:
- [BEST_SAMPLE_STRUCTURE.md](./BEST_SAMPLE_STRUCTURE.md) - Directory structure templates
- [VALIDATION_CHECKLIST.md](./VALIDATION_CHECKLIST.md) - Comprehensive validation checklist

## Pre-Submission Checklist

Before submitting your sample, ensure:

- [ ] All features and dependencies exist and are documented
- [ ] Sample works end-to-end with fresh installation
- [ ] No hardcoded credentials, API keys, or AWS Account IDs
- [ ] Documentation accurately reflects implementation



## Documentation Standards

### Accuracy Requirements

**Match Implementation to Documentation**
- Claims in README must match actual code functionality
- Architecture descriptions must reflect actual implementation


- Be consistent with terminology across all documentation


## Review Process

### What Reviewers Check

**Functionality**
- Sample runs without errors
- All features work as documented
- Examples execute successfully

**Documentation**
- Accurate and complete
- Clear setup instructions
- Working code examples

**Code Quality**
- Follows best practices
- Proper error handling
- No security issues

### Iterating on Feedback

When reviewers request changes:

1. **Review feedback carefully** - Understand the specific concerns
2. **Ask questions if unclear** - Clarify requirements before implementing
3. **Make requested changes** - Address all feedback points
4. **Test thoroughly** - Re-verify functionality after changes
5. **Update documentation** - Keep README in sync with code changes
